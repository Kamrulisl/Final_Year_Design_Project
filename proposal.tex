\section{What This Project Is About}

In Bangladesh, civil documents like the National Identity Card (NID),
Birth Certificate, and Academic Certificate are very important for every
person. A very common problem is that the same person's name, date of
birth, or address is written in different ways in different documents.
This causes problems at government offices, job applications, and passport work.

The problem gets worse in a family. A child's documents must show the same
parent names that are in the parents' own documents. If the child's Father
Name field does not match the father's NID name, the family must go through
a long correction process.

Right now, the government correction process works by hand. A user applies
to fix one document at a time and an officer checks it manually. There is no
system that looks at all family documents together and finds all problems
before the correction is applied.

\vspace{0.4cm}
\textbf{This project builds a system that:}

\begin{enumerate}
    \item Takes all family member document data from an Excel file.
    \item Finds every place where each person's name is written across all
          family documents.
    \item Counts which name version appears most and uses that as the correct value.
    \item Finds small name mistakes and serious name mismatches.
    \item Checks dates, parent-child age gaps, and address spellings.
    \item Gives a mismatch report and fix suggestions in an Excel output file.
\end{enumerate}

% ─────────────────────────────────────────
%  2. THE MAIN NEW IDEA
% ─────────────────────────────────────────
\section{The Main New Idea}

The main new idea is the \textbf{Family Document Graph with a Consensus Method}.

In a family, one person's name appears in many places. For example, the
father's name is written in:

\begin{center}
\begin{tabular}{|p{6cm}|p{5cm}|}
    \hline
    \textbf{Document / Field} & \textbf{Name Written} \\
    \hline
    Father's own NID & Md. Ali \\
    \hline
    Father's own Birth Certificate & Mohammad Ali \\
    \hline
    Father's own Academic Certificate & Md. Ali \\
    \hline
    Son's Birth Certificate --- Father Name & Mohammad Ali \\
    \hline
    Son's NID --- Father Name & Md. Ali \\
    \hline
    Son's Certificate --- Father Name & Md. Ali \\
    \hline
    Daughter's Birth Certificate --- Father Name & Mohammad Ali \\
    \hline
    Daughter's NID --- Father Name & Md. Ali \\
    \hline
\end{tabular}
\end{center}

\vspace{0.3cm}
The system collects all these values and counts them:

\begin{itemize}
    \item \textbf{``Md. Ali''} --- 5 times $\rightarrow$ Most common
          $\rightarrow$ \textbf{This is the correct value}
    \item \textbf{``Mohammad Ali''} --- 3 times $\rightarrow$ Small name mistake
\end{itemize}

\textbf{Fix suggestion:} All documents should use ``Md. Ali''.

\vspace{0.4cm}
This same method is used for the mother's name and each child's own name
across all their documents. No current system does this.

% ─────────────────────────────────────────
%  3. WHAT THE SYSTEM CHECKS
% ─────────────────────────────────────────
\section{What the System Checks}

\subsection{Name Check}

For every person in the family, the system finds all written versions of
their name from all related family documents, counts each version, and
picks the most common one. Other versions are marked as:

\begin{itemize}
    \item \textcolor{orange}{\textbf{Small Mistake}} --- Only a short form
          or spelling difference. Example: ``Md. Ali'' vs.\ ``Mohammad Ali''.
    \item \textcolor{red}{\textbf{Serious Mismatch}} --- The main name is
          completely different. Example: ``Mohammad Ali'' vs.\ ``Md. Akib''.
          This needs a senior officer to check.
\end{itemize}

\subsection{Date of Birth Check}

All date values are first converted to one standard format.
Then the real dates are compared. Two cases are possible:

\begin{itemize}
    \item \textbf{Format difference only:} ``01/05/1995'' and ``1995-05-01''
          are the same real date. This is \textcolor{green}{not a mismatch}.
    \item \textbf{Real date difference:} ``2002-03-03'' in NID and
          ``2000-02-02'' in Birth Certificate are two different dates.
          This is a \textcolor{red}{true DOB mismatch} and needs
          officer verification.
\end{itemize}

\subsection{Parent-Child Age Gap Check}

A parent must be older than their child by a proper number of years.
The system checks the real year difference between parent and child DOB.
If the gap is too small or invalid, the system marks it as a problem.

\begin{itemize}
    \item \textbf{Valid example:} Father born 1980, Son born 2005 ---
          gap is 25 years. \textcolor{green}{Valid.}
    \item \textbf{Invalid example:} Father born 1980, Child born 1982 ---
          gap is only 2 years. \textcolor{red}{Invalid.}
\end{itemize}

\subsection{Address Check}

Division, District, Upazila, Union, City Corporation, and Pourosova names
are checked against a fixed spelling list. If a document uses a wrong
spelling, the system suggests the correct one. For example, if a document
writes ``Chittagong'' but the fixed spelling is ``Chattogram'', the system
suggests ``Chattogram''.

% ─────────────────────────────────────────
%  4. WHY THIS IS RESEARCH
% ─────────────────────────────────────────
\section{Why This Is Research}

\subsection{Research Question}

\begin{quote}
\textit{Does a consensus-based Family Document Graph give better results
than the current manual single-correction process for finding and fixing
name problems in Bangladesh civil registry documents?}
\end{quote}

\subsection{Research Gap}

No current system does what this project does:

\begin{enumerate}
    \item No system collects one person's name from all related family
          documents and uses a counting method to find the correct value.
    \item The current government correction process works one application
          at a time. It does not find all family-level problems at once.
    \item No system separates small name mistakes from serious mismatches
          automatically.
    \item No system checks the parent-child age gap across all related documents.
    \item No Bangladesh-specific automatic system exists for this problem.
\end{enumerate}

\subsection{How the Research Will Be Done}

\begin{enumerate}
    \item \textbf{Make a test dataset:} 50 to 100 family records in Excel
          files, with different types of name mistakes, date problems, age
          gap problems, and address problems. The correct answer for each
          record will be marked by hand.

    \item \textbf{Build the old method:} The current one-at-a-time correction
          process will be built and tested on the same dataset as a baseline.

    \item \textbf{Build the new method:} The Family Document Graph and
          Consensus Method will be built and tested on the same dataset.

    \item \textbf{Compare both:} The results will be compared using Accuracy,
          Precision, Recall, and F1-Score to show which method works better.
\end{enumerate}

% ─────────────────────────────────────────
%  5. KNOWN LIMITATIONS
% ─────────────────────────────────────────
\section{Known Limitations}

Every system has cases where it may not work well. The following cases
are known limitations of the proposed method.

\subsection{When Most Documents Have the Wrong Value}

The consensus method picks the name that appears most often. If most
documents in the family contain the wrong name, the system will pick
that wrong name as the correct value.

\begin{center}
\begin{tabular}{|p{5.5cm}|p{5.5cm}|}
    \hline
    \textbf{Example} & \textbf{What Happens} \\
    \hline
    Father's NID: Md. Ali \newline
    Son's Birth F.Name: Karim Hossain \newline
    Son's NID F.Name: Karim Hossain \newline
    Daughter's NID F.Name: Karim Hossain &
    ``Karim Hossain'' wins the count (3 vs 1). \newline
    System picks a wrong value as correct. \\
    \hline
\end{tabular}
\end{center}

\textbf{Partial fix:} The system gives extra weight to the Father's own
NID field, since this is the most trusted document.

\subsection{When Only One Document Exists}

If a person has only one document, the system cannot count and compare.
There is nothing to check against. The system will mark this as
``not enough data'' instead of giving a suggestion.

\subsection{When Bengali and English Are Mixed}

The system may count the Bengali script version and
``Mohammad Ali'' (English) as two different names, even though they
are the same name. This can lower the count for the correct value.

\textbf{Partial fix:} Bengali name values will be converted to English
using a simple transliteration step before counting.

\subsection{When the Child's Parent Name Is Completely Different}

If a child's document shows a completely different name in the Father
Name field (not just a spelling difference), the system marks this as
a serious mismatch and asks for officer verification. However, the
system cannot tell \textit{why} the name is different --- it could be
a data entry error or a genuinely different person.

\vspace{0.3cm}
\textbf{Summary of known failure cases:}

\begin{center}
\begin{tabular}{|p{5cm}|p{3cm}|p{4.5cm}|}
    \hline
    \textbf{Case} & \textbf{System Result} & \textbf{Partial Fix} \\
    \hline
    Wrong name in most documents & Wrong consensus & Weight NID more \\
    \hline
    Only one document per person & No suggestion & Mark as low data \\
    \hline
    Bengali and English mixed & Low count & Transliterate first \\
    \hline
    Child doc shows fully different parent name & Serious mismatch flag & Officer check \\
    \hline
    Two different real DOB values & True DOB mismatch & Officer check \\
    \hline
\end{tabular}
\end{center}

These limitations will be discussed in the final report and can become
areas for future improvement.

\section{Input and Output}

\subsection{Input}

Family data will be entered through an \textbf{Excel file}. Each row contains
one person's document data. The Excel file will have these columns:

\vspace{0.2cm}
Family ID, Person ID, Role (Father / Mother / Son / Daughter), NID Name,
Birth Certificate Name, Academic Certificate Name, Father Name, Mother Name,
Date of Birth, Division, District, Upazila, Union, City Corporation or
Pourosova, and Address details.

\subsection{Output}

The system will give two outputs:

\begin{itemize}
    \item \textbf{Excel report file} --- Shows the correct value, mismatch
          type, and fix suggestion for each field and each person.
    \item \textbf{PDF summary report} --- A clear summary of all found
          problems and suggestions for the whole family.
\end{itemize}

\section{Conclusion}

This project builds a new system that finds name problems, date problems,
age gap problems, and address problems in Bangladesh civil documents at the
family level. The main new idea is to collect every version of a person's
name from all family documents, count which version appears most, and use
that as the correct value. The project also knows its own limits --- for
example, when most documents contain the wrong value, or when only one
document exists, the system may not give a good result. These limits will
be discussed in the final report. This project covers Database Design,
Software Engineering, and Data Science. It works on a real problem that
affects millions of people in Bangladesh, making it a good fit for the
Final Year Design Project of the B.Sc. in CSE program at Premier University
Chittagong.
